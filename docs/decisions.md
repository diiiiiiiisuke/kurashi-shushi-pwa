# 判断記録

決めたことと理由を残す。新しいものを下に追加する。

## 2026-10-12 依存なし・ビルドなしの静的PWAにする
- 理由: スマホのGitHub上で直接編集でき、Codex・Claude どちらでもすぐ動かせる。ビルド環境の差による齟齬が出ない
- 影響: フレームワーク・npmパッケージは使わない。必要になったら事前にここで再検討する

## 2026-10-12 データは端末の localStorage のみに保存する
- 理由: 家計データを外部サーバーに置かない。公開リポジトリでも安全
- 影響: 端末変更・ブラウザデータ削除で消えるため、設定画面のバックアップ（JSON）で移行する

## 2026-10-12 ドキュメントは AGENTS.md と docs/ に集約する
- 理由: 普段はCodex、ときどきClaude Codeを使うため、会話ではなくリポジトリを唯一の情報源にする
- 影響: `CLAUDE.md` は `AGENTS.md` を参照するだけにして、ルールを二重管理しない。作業ごとに `docs/worklog.md` と `docs/roadmap.md` を更新する

## 2026-10-12 アプリ本体はリポジトリのルートに置く
- 理由: GitHub Pages が `main` のルートを配信する設定で既に動いているため。フォルダ移動すると公開URLやPages設定の変更が必要になる
- 影響: ドキュメントは `docs/`、スクリプトは `scripts/` に分ける。`docs/` もPagesで配信されるが、公開リポジトリなので問題ない

## 2026-10-12 Service Worker はネットワーク優先にする
- 理由: キャッシュ優先だと、更新してもスマホに古い版が残り続ける
- 影響: オンライン時は常に最新版。`CACHE` の番号は変更のたびに上げる

## 2026-10-12 データ形式の変更は load() でマイグレーションする
- 理由: 保存キー `kurashi-shushi-data-v1` を変えると既存データが見えなくなる
- 影響: 形式を変えるときは旧データを新形式に変換する処理を `load()` に追加する

## 2026-10-12 CSPで外部通信を禁止する
- 理由: 家計データの流出を、コードの書き間違いや外部スクリプトの混入があってもブラウザ側で止めるため
- 影響: 外部API・CDN・解析タグは使えない。必要になったらオーナーの許可を取り、`docs/security.md` とここを更新する

## 2026-10-12 v2 の要確認事項 Q1〜Q5 を確定
- 返済方式の初期値は「定額（利息込み）」、作戦の初期値は「金利の高い順」、カード払いは使った日で記録、ホームは個人＋事業の合算、初期カテゴリは spec-v2.md 3.2 のまま
- 理由: オーナーが「すべて仮の決定でOK」と回答

## 2026-10-12 返済先の現在残高は保存せず計算する
- 理由: 返済記録を編集・削除しても残高がずれないようにするため
- 影響: 明細と誤差が出たら「明細の残高に合わせる」で基準残高と日付を更新する

## 2026-10-12 ES Modules に分割し、package.json は "type": "module" だけ置く
- 理由: ビルドなしのまま機能ごとにファイルを分け、計算部分を Node 標準のテストランナーでテストするため
- 影響: npm パッケージは入れない。`node --test` だけで動く

## 2026-10-12 記録タブを Notion風の「家計簿DB」にする
- 理由: オーナーの依頼（Notion の DB のように管理し、毎日・月次などをプルダウンで切り替えたい）
- 影響: ビューは `settings.recordsView` に保存（データ形式の変更なし）。スマホで金額が見えるよう、金額は2列目に固定

## 2026-10-12 返済グラフの過去分は返済記録から逆算する
- 理由: 残高の履歴を別に保存すると二重管理になるため。基準残高と返済記録の元金があれば月末残高を再現できる
- 影響: 基準日より前の返済記録がない期間の実績は表示しない（最初の記録の月から最大12か月）

## 2026-10-12 保有クレカの名前はリポジトリに書かず、アプリで貼り付けて登録する
- 理由: リポジトリは公開のため、カード名を書くと保有カードが公開される。アプリのデータはスマホ内にしかなく、開発側からは書き込めない。Notion へもこの環境からはアクセスできない
- 影響: 「まとめて追加」機能を用意し、オーナーが Notion の「名前」列をコピー＆貼り付けする

## 2026-10-12 使用中の支払方法は削除せず非表示にする
- 理由: 過去の記録が参照しているため、削除すると記録の支払方法が「不明」になる
- 影響: 未使用なら削除、使用中なら「使わない（非表示）」。入力の選択肢から消え、集計には残る

## 2026-10-12 セキュリティを「自動チェック＋人のマージ＋アプリのロック」で守る
- 理由: オーナーが普段は Codex にスマホから依頼して開発するため、AI の変更が家計データを外部に送る経路を作らないことを仕組みで担保したい
- 影響: `scripts/security-check.mjs` を CI で実行（外部通信・外部URL・CSP変更・ワークフロー権限・未固定アクションを検出）。CSP・チェック・ワークフロー・暗号まわりは、オーナーの明示的な許可なしに変更しない（AGENTS.md）。自動マージは使わない
- アプリ: PINロック（ハッシュのみ保存、ロック中は記録を描画しない）と暗号化バックアップ（AES-GCM）。端末内データの暗号化は、PIN を忘れたときに復元できなくなるため今回は見送り
- GitHub の設定（main の保護ルール・Actions の権限など）は AI から変更できないため、手順を docs/security.md 4章に書きオーナーが行う

## 2026-10-12 公開先を GitHub Pages から Cloudflare Pages に移す
- 理由: オーナーが今後、同じ GitHub アカウントで別のサイトを公開するかもしれないため。github.io のままだと同じドメインの別サイトから家計データ（ブラウザの保存領域）を読まれうる。本番の記録を入れる前の今が、移行の手間が最も小さい
- 影響: `scripts/build-site.sh` で公開ファイルだけを `dist/` に集め、`_headers` でセキュリティ用ヘッダー（CSP＋frame-ancestors など）を返す。どちらも `scripts/check.sh`・`security-check.mjs` で検査。移行後は github.io のデータを消して GitHub Pages を停止する（`docs/deploy.md`）
- リポジトリは公開のまま（非公開にするかは別途判断）

## 2026-10-12 Cloudflare は Pages ではなく Workers（静的アセット）で公開する
- 理由: Cloudflare の作成画面が Workers を標準にしており、オーナーが Workers で作成した。作り直すより設定ファイルを足す方が早い。機能（専用ドメイン・自動公開・プレビュー・`_headers`）は Pages と同等
- 影響: `wrangler.jsonc` を追加（サーバー側のコードなし、`dist/` を配るだけ）。`security-check.mjs` で `main` や外部サービス接続の追加を禁止。URL は `kurashi-shushi-pwa.<サブドメイン>.workers.dev`

## 2026-10-12 バックアップは「週1回の催促＋1タップで iCloud に保存」、パスワードは任意
- 理由: オーナーが毎回のバックアップを面倒と感じたため。ホーム画面の Web アプリは iCloud へ自動保存できないので、手間を最小（約5秒）にする。完全自動（サーバーへの同期）は「データを外部に出さない」方針と相反するため見送り
- 影響: 初期はパスワードなし（保存先の iCloud が Apple ID で守られているため）。パスワード付きも選べる。`navigator.storage.persist()` で保存領域を消えにくくする。詳細は `docs/spec-backup.md`

## 2026-10-12 — 返済情報を返済タブへ集約

- オーナー依頼に沿って、ホームは収支サマリに絞り、ホーム・分析にあった返済専用のグラフ/概要を返済タブに移す
- カード別の次回引き落としは既存の支払方法・締日・支払日・取引・定期取引から計算する。標準は締日の翌月払い。請求未確定の概算として明示し、日付未設定分を合計に混ぜない
- 分割・リボ・ローンの返済記録はカード一括払いの合計から除外。返済先と支払方法の自動的な名前照合は行わず、二重計上を避ける
- 保存形式・既存の取引データは変更しない

## 2026-10-12 — 分析グラフの日別・週別・月別切替

- オーナー依頼に沿って、グラフ左上に集計単位のプルダウンを置く
- 日/週は画面上部で選んだ月、月別は既存の直近12か月を表示。週は月曜始まりで、月境界の週を選択月内に切り詰める
- 平均も記録のある日/週/月に合わせる。表示の選択は画面状態だけに保持し、家計データや保存形式は変更しない
